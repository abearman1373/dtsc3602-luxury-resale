## Frontend (`web/index.html`)
A single static page (no build step — deployed to Vercel as-is) that calls the live D4 API directly from
the browser via `fetch`:

- **Inputs**: brand, item group, product type, material, condition, age band, microchip flag, estimated
  retail price, extras count and four extras checkboxes — the same fields `POST /predict` accepts.
- **Loading state**: a spinner + "Calling the live model…" message while the request is in flight; the
  submit button disables to prevent double-submits.
- **Error state**: a non-422/503 network failure (e.g. a cold-starting container) shows a retry hint; a
  422 from the API renders the specific field error Pydantic returned; a 503 says the model is temporarily
  unavailable. Nothing fails silently.
- **Result**: the predicted ratio, a derived ballpark asking price, and the model version (git commit) the
  prediction came from.

CORS: `api/main.py` allows all origins for `/health`, `/info`, `/predict` (read-only endpoints, no
cookies/auth) so the Vercel-hosted page can call the Modal-hosted API cross-origin.

**Verified live**: filled the form on the deployed Vercel URL, submitted, and confirmed the loading state
appeared then resolved to a result identical to the equivalent direct API call (`57.9%` / `$1,274.20` for
Louis Vuitton / Handbag / Totes / Very Good / "Not available" age / $2,200 retail).
