# D4: Fitted Pipeline and API

## Artifact
- `scripts/train_final_pipeline.py` fits the D3-selected model (Ridge, α=10) on the **full** `train_val.csv`
  (1,843 rows) and saves `models/pipeline.joblib` + `models/metadata.json`. `test_holdout.csv` is still never
  opened — this is the frozen model D6 will evaluate against it.
- The pipeline is a single `sklearn.pipeline.Pipeline`: `ColumnTransformer` (`RareCategoryGrouper` → one-hot
  for 5 categorical columns; `StandardScaler` for 8 numeric columns) → `Ridge`.
- **Custom transformer**: `scripts/transformers.py::RareCategoryGrouper` — folds any category seen fewer
  than 10 times in training (or never seen at all) into `"Other"`, fit on training data only. See
  `docs/d3_model_evaluation.md` for why it's needed (`product_type` has 25 raw values, several with n<3).
- Rebuild: `uv run python scripts/train_final_pipeline.py` (reproducible — same seed, same source CSV).

## API (`api/main.py`)
FastAPI service, loads the artifact once per process at import time (module-level global — never retrains
during serving).

| Endpoint | Behavior |
|---|---|
| `GET /health` | `200 {"status":"ok"}`, or **503** if the artifact failed to load |
| `GET /info` | Pipeline metadata (model type, features, training provenance), or **503** |
| `POST /predict` | Valid request → `200` with `asking_price_ratio` + `estimated_asking_price`. Invalid input (bad enum, non-positive price, etc.) → **422** automatically via Pydantic `Literal` + `Field` constraints. Artifact unavailable → **503**. |

Interactive schema/docs: `/docs` (Swagger UI), generated by FastAPI from the Pydantic models.

### Verified checks
- **422**: posted an unknown `brand_group` and a negative `estimated_retail_price` — both returned 422 with
  a field-level error message, locally and on the deployed API.
- **503 (tested locally only, without touching the live app)**: moved `models/pipeline.joblib` aside,
  restarted the local server — `/health` and `/predict` both returned 503 with the underlying error in
  `detail`, and the process itself stayed up (didn't crash). Artifact restored and the live app was never
  taken down for this test.
- **Local vs. deployed match**: posted the identical request body to the local server and the deployed Modal
  URL — both returned byte-identical JSON: `{"asking_price_ratio":69.0,"estimated_asking_price":1517.9,"model_version":"170764f"}`.

## Deployment (`api/modal_app.py`)
Wraps the FastAPI app with `@modal.asgi_app()`. The Modal image pins **scikit-learn 1.9.1 / pandas 3.1.0 /
numpy 2.5.4** — the exact versions used to fit `pipeline.joblib` — since a version mismatch can silently
change how a fitted estimator unpickles. Mounts `api/main.py`, `scripts/transformers.py` (required for
`joblib.load` to resolve the custom transformer's class), and the two files in `models/`.

```powershell
uv run modal setup
uv run modal deploy api/modal_app.py
```

- **API URL**: https://abearman1373--luxury-resale-api-fastapi-app.us-east.modal.run
- **Docs**: https://abearman1373--luxury-resale-api-fastapi-app.us-east.modal.run/docs

Like the D2 dashboard, this Modal app scales to zero when idle — the first request after a quiet period
takes several seconds for a cold start (observed ~7s), then responds normally.
